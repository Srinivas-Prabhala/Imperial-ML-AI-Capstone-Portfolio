# Module 21.1 — Refining the Black-Box Optimisation Strategy
## Section A: Round 10 query strategy reflection

### 1. Reasoning behind the Round 10 query choices

The Round 10 decisions are informed by the cumulative record of the original observations and the nine weekly submissions (Modules 12.1–20.1). All eight functions are maximisation problems, so a higher output is preferable, including when the values are negative. The incumbent best observation is retained separately for each function; a new query is not assumed to improve on it.

The historical record shows different patterns across functions. F1, F5, F7 and F8 established new cumulative bests in Week 9. F5 had also improved in each of Weeks 7–9, while F7 improved across Weeks 6–9. By contrast, the best observations for F2, F3, F4 and F6 came from earlier rounds (Weeks 2, 7, 5 and 8 respectively). These differences support a function-specific rather than uniform strategy. The Week 9 allocation used PI for F1 and F6, EI for F2, F4, F5 and F7, and UCB for F3 and F8. Four functions improved their cumulative best in that round: F1, F5, F7 and F8.

For Round 10, the next query for each function should be selected using its complete historical input-output record and the corresponding Gaussian Process (GP) posterior and acquisition-function evidence. The recent improvement of a function is useful context, but is not by itself proof that the same acquisition function is optimal. The selected coordinates and the acquisition scores should be recorded with the final portal submission.

### 2. Transparency and reproducibility

The cumulative dataset preserves the original observations and appends each weekly input-output pair chronologically. Each record identifies the function, input coordinates, observed output and whether it is an initial observation or a weekly submission. The cumulative summary records the incumbent best, the round in which it was achieved, and whether the latest round improved it.

A researcher could reproduce the data analysis if given the original `.npy` observation arrays, the weekly input-output records, and the query-selection notebook. To reproduce the optimisation decisions fully, the record should also include the GP kernel and hyperparameters, preprocessing choices, acquisition-function formula and parameters (including the UCB exploration parameter), candidate-generation method, random seed, optimisation bounds and software versions. Some earlier acquisition allocations and model settings are not fully specified in the current cumulative record; these should not be inferred retrospectively.

### 3. Assumptions underlying the strategy

The approach assumes that the objective functions are deterministic or sufficiently stable for observed input-output pairs to be informative; that the input coordinates are valid within the specified unit hypercube; and that a GP surrogate provides a useful approximation of each function over the sampled region. It also assumes that the maximisation objective and the recorded portal outputs are consistent across rounds. If the functions are noisy, discontinuous, highly irregular or poorly represented by the chosen GP kernel, posterior uncertainty and acquisition rankings may be misleading.

### 4. Data gaps and potential sampling bias

The query distribution is not uniform. Later submissions increasingly use information from previously promising regions, which is intentional exploitation but leaves other parts of the input space sparsely sampled. This is especially relevant for higher-dimensional functions, where a small number of observations covers only a limited portion of the possible space. The cumulative record also documents Week 8 and Week 9 acquisition allocations more explicitly than some earlier rounds. Consequently, comparisons between acquisition functions are descriptive rather than controlled causal comparisons. The available data do not establish that one acquisition function is universally superior.

### 5. Limitations

The main limitation is the small number of evaluations relative to the size of the search spaces, particularly for functions with five to eight dimensions. GP performance depends on kernel choice, hyperparameters, scaling and the distribution of observed points. Different acquisition parameters or candidate-search procedures could produce different suggestions. The best observed value is not proof of the global optimum. In addition, the functions have different output scales, so raw objective values should not be compared directly across functions.

The project therefore treats each new query as an evidence-informed experiment, retains the historical incumbent, and updates conclusions only after receiving the actual function evaluation. The additional query allowance is optional in the task wording; this submission focuses on the required one new query per function rather than adding experiments that are not needed to satisfy the stated deliverable.
